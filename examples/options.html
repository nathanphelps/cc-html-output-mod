Where to cache report results

The Reports page runs the same aggregate query every time it loads, and the query takes 4 to 9 seconds on the production database. Most users open the page several times a day with the same filters. Data that is up to 15 minutes old is acceptable.

Recommendation: option B

It meets the 1-second goal for repeated views, gives every user the same numbers, and uses infrastructure we already run. Option A is faster to build but shows inconsistent totals. Option C is the only one that fixes the first view, and it is worth revisiting if first-view time becomes the main complaint.

What would change this recommendation

  • If more than half of page loads are first views, choose C.
  • If results are regularly larger than 5 MB, choose C.
  • If this is needed before the end of the week, ship A and replace it with B.
