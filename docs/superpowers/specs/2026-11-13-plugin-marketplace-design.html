Intent

Today a person installs this project by pasting PROMPT.md into a session or by copying files. Nathan wants three things the current route does not give (his words: "easier install and automatic updates as I develop it, and also allow community contributions"):

  • Easier install: add a marketplace, install a plugin.
  • Updates that reach users as the rule and skill change.
  • Community contributions: a repo layout and checks that let other people send changes.

Goals

  • Installable from this GitHub repo on Claude Code and on Codex
  • The rule is active in every session after install, without editing CLAUDE.md or AGENTS.md
  • A change to the rule or skill on main reaches installed users through the tool's plugin update
  • The offline/CDN choice and rewording remain possible
  • Removing the plugin removes everything it added
  • The existing paste-the-prompt and by-hand routes keep working

Non-goals

  • Other agents (Cursor, Gemini, and so on)
  • Submission to Anthropic's or OpenAI's public plugin directories. Codex's directory does not accept plugins with hooks
  • Changing the rule's wording or the skill's content
  • Detecting or removing a rule the user already pasted
  • A configuration interview inside the plugin

Would make this a failure

  • The hook prints an error, or noticeably delays session start, on any of Windows, macOS, Linux
  • The hook fails on Windows when Git Bash is not installed
  • An existing paste install stops working
  • The rule text exists in two files in the repo that can drift apart unnoticed

Approaches considered

A plugin can carry skills and hooks but has no place for always-on instruction text, so the question was how the rule gets into each session.

A. Hook prints the rule picked by Nathan

A session-start hook prints the rule from a file in the plugin, or from the user's override file.

  • Rule changes reach users with plugin updates
  • Uninstall is removing the plugin
  • Costs: Codex trust step; not eligible for Codex's public directory; needs a script that runs on three operating systems; a user who already pasted the rule has it twice

Why: it is the only option that delivers rule updates, which is one of the three stated goals.

B. Plugin ships a setup skill

The plugin holds the skill plus a setup skill that runs the PROMPT.md interview and writes the rule into the user's files.

  • Keeps all four install methods and the wording questions
  • Eligible for public directories; no hook
  • Cost: the pasted rule never updates; uninstall means editing files

C. Both

Hook by default, setup skill for people who want the rule in their own files.

  • Covers every preference
  • Cost: two paths to build, document, and support; a user can end up with both active

Behavior of the hook

  • Runs on every session-start source (new session, resume, clear, compact). After a compaction the earlier instructions may be summarized away, so the rule is printed again.
  • Output is the rule file's text exactly, starting with its # Document format heading, and nothing else.
  • Override path is $HOME/.config/html-documents/rule.md on macOS and Linux and %USERPROFILE%\.config\html-documents\rule.md on Windows. An empty or whitespace-only file counts as absent.
  • No dependency on Node, Python, or Git Bash. Claude Code runs hook commands under Git Bash on Windows when it is installed and under PowerShell otherwise; Codex's Windows behavior is not documented. The script has to work in each case. A single file that is valid both as a Windows batch file and as a POSIX shell script (the pattern Superpowers uses in hooks/run-hook.cmd) meets this with type on Windows and cat elsewhere.
  • Failure is silent. If neither file can be read, the script prints nothing and exits 0. A session without the rule is better than a session that starts with an error.
  • Size. Claude Code caps hook output at 10,000 characters. The rule is about 1,600. The README states the cap for override files.

Checks

CI (.github/workflows/check.yml)

  • Every manifest and hooks file parses as JSON.
  • The text between <!-- rule:start --> and <!-- rule:end --> in PROMPT.md equals html-output-rule.md.
  • The hook test passes on Ubuntu, macOS, and Windows runners. On Windows it runs the script through cmd.exe, through PowerShell, and through Git Bash.
  • claude plugin validate . --strict if it can run in CI without signing in; otherwise it is a documented local step in CONTRIBUTING.md.

Manual, on this machine before release (both tools are installed here)

This machine already has the rule pasted in ~/.codex/AGENTS.md, imported by ~/.claude/CLAUDE.md. A "quote your Document format instruction" test would pass without the plugin. Test with an override file that contains a marker sentence, and check for the marker. Do not edit the global instruction files.
  1. Claude Code: add the marketplace from the local path, install, run claude -p asking it to quote the marker sentence. Confirm the skill is listed. Run claude plugin validate ..
  2. Codex: add the marketplace, codex plugin add, trust the hook, run codex exec --skip-git-repo-check with the same question. Confirm the skill is listed.
  3. Remove the override; confirm the default rule is what arrives (compare against a temporary edit of the plugin's rule file with a marker, then revert).
  4. Uninstall on both tools and confirm nothing remains except the override folder, which the README says to delete by hand.

Left to the builder

  • The hook script's name and exact implementation, within the behavior above.
  • Description, keyword, and interface text in the manifests, taken from the README's first paragraph.
  • The layout of the test script(s) and the CI workflow.
  • Wording and order of the README changes, in the README's existing plain style, and written to the standard in the repo owner's writing instructions (literal statements, no figurative phrasing).
  • Whether .agents/plugins/marketplace.json and a Codex-specific hooks file are needed, decided by the tests in the table above.

Allowed: creating a feature branch, committing to it, and pushing it to origin so CI runs. Not in scope without asking: committing to or merging into main, opening a pull request, tagging a release, renaming the repository, or editing the user's global instruction files.
